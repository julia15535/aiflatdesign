# Шаблон файла плана

Все планы в проекте пишутся одним форматом. Лежат в `.memory_bank/plans/` пока в работе. После завершения переезжают в `.memory_bank/completed_plans/`.

## Когда нужен файл плана

- Задача больше 3 шагов
- Работа займёт больше одной сессии — нужно записать прогресс
- Важно зафиксировать почему сделали именно так (контекст пригодится через месяц)

Маленькие задачи (правка 1-2 файлов, простое изменение) — без плана, сразу делать.

## Структура файла

```markdown
# План: {Краткое название}

**Статус:** В работе / Выполнено
**Создан:** {дата формата 2026-05-11}
**Последнее обновление:** {дата}

---

## Цель

{1-3 предложения — что хотим в результате, почему это важно}

## Контекст

{Опционально — что подтолкнуло этот план, какие решения уже приняты, какие альтернативы рассматривали}

## Задачи

- [ ] Задача 1 — короткое описание
- [ ] Задача 2
- [x] Задача 3 — выполнено {дата}, {краткое описание если важно понимать как именно}

## Лог выполнения

### {дата}
- Выполнено: {что сделано}
- Проблемы: {если были}
- Решения: {если что-то изменилось в подходе}
```

## Правила

1. **Имя файла** — короткое, понятное, snake_case по-английски: `day_1_bot_skeleton.md`, `fix_image_compression.md`. Не "task_4.md" (через неделю не вспомнишь).

2. **Дата** — всегда абсолютная (`2026-05-11`), не "вчера/завтра". Через 3 месяца "завтра" уже непонятно.

3. **Галочки `[x]`** — ставить как только задача сделана, не копить.

4. **Лог выполнения** — добавлять по дате. Если в один день несколько подходов — несколько подзаголовков в этой дате.

5. **При завершении плана**:
   - Изменить статус на "Выполнено"
   - Добавить дату завершения
   - Перенести файл из `plans/` в `completed_plans/`

## Пример живого плана

См. `plans/day_0_setup_and_audit.md` (если ещё в работе) или `completed_plans/day_0_setup_and_audit.md` (если уже сделан).

## Чего не делаем в планах

- ❌ Полные примеры кода — для этого есть `.memory_bank/ai/`, `.memory_bank/bot/` и сам код
- ❌ Описание архитектуры — это в `CLAUDE.md` или специализированных файлах
- ❌ Длинные перепалки "почему именно так" — в `_claude/DECISIONS.md`
- ❌ Бюджетные расчёты — в `business/budget.md`

План — это **что делаем, в каком порядке, и что уже сделано**. Не больше.
