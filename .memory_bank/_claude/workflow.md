# Claude workflow в этом проекте

Правила работы Claude Code'а с memory bank'ом и проектом aiflatdesigner.

## При старте каждой сессии

1. **Прочитать `MEMORY.md`** в auto-memory (`C:\Users\mycor\.claude\projects\c--Users-mycor-aiflatdesigner\memory\`) — там pointer'ы на этот memory bank.
2. **Заглянуть в `.memory_bank/plans/`** — есть незавершённые планы? Если да — предложить продолжить.
3. **Открыть `.memory_bank/CLAUDE.md`** — это manifest проекта.
4. **Если фича/баг** — прочитать `domain/`, `ai/<нужный stage>.md`, `bot/<нужный area>.md`.

## При фиче >3 шагов

1. Создать `plans/<name>.md` со структурой:

```markdown
# План: {Название}

**Статус:** В работе
**Создан:** YYYY-MM-DD
**Последнее обновление:** YYYY-MM-DD

## Цель
{что хотим в результате}

## Задачи
- [ ] Задача 1
- [ ] Задача 2

## Лог выполнения
### YYYY-MM-DD
- Выполнено: {что}
- Проблемы: {если были}
```

2. По мере выполнения — ставить `[x]`, обновлять дату.
3. По окончании — статус "Выполнено", переместить в `completed_plans/`.

## При архитектурном решении

Записать в `_claude/DECISIONS.md` в формате:

```markdown
## YYYY-MM-DD: {Заголовок}

**Решение**: {что}

**Альтернативы**: {что рассматривали и почему отказались}

**Trade-off**: {плюсы и минусы выбранного}

**Триггер**: {когда пересмотреть}
```

## При деплое / изменении prod

Записать в `_claude/DEPLOY.md` (или обновить существующее) команды/события.

## Дата

Конвертирую относительные даты в абсолютные при записи:
- "Завтра" → "2026-05-12"
- "через неделю" → "2026-05-18"
- "в пятницу" → "2026-05-15"

## Язык

- Документация (md-файлы, README) — **русский**
- Имена переменных/функций/файлов — **английский**
- Команды и технические термины — **английский**

## Стиль документации

- ✅ Концепции и **почему**, не **как именно**
- ✅ Таблицы сравнений (до 5 строк)
- ✅ Краткие списки
- ❌ Длинные примеры кода (>10 строк) — давать только если без них не понять
- ❌ ASCII-зарисовки экранов
- ❌ Полные реализации классов

## Перед коммитом

- ✅ `.env` НЕ в diff'е
- ✅ `_claude/SECRETS.md` НЕ в diff'е (gitignored)
- ✅ `data/*.db` НЕ в diff'е (gitignored)
- ✅ Хотя бы одно осмысленное сообщение коммита, не "wip"
- ✅ Тесты не падают (если есть)

## Анти-паттерны

- ❌ Запоминать секреты в системной Claude memory — только в `_claude/SECRETS.md`.
- ❌ Запускать `docker compose up` на dev-машине без понимания что мы локально тестируем (или подключать сервер).
- ❌ Дублировать контент между MVP_PROTOTYPE_v4.md и memory bank'ом. Memory bank — **сжатый справочник**, не копия.
- ❌ Создавать `business/`, `analytics/` итд если они не нужны в MVP — лишний шум.

## Что отличается от референса (memory_bank_reference)

- **Один продукт** (не 3 шары — admin / mobile / backend) → проще структура
- **Без `mobile/`, `analytics/`, `screens/`** — не нужно для бота
- **Без `backend/apis/`** — у нас нет внутренних API, только внешние (OpenAI, Replicate, Telegram)
- **Свой `ai/`** — основная сложность проекта в AI pipeline
- **Свой `bot/`** — все детали Telegram-слоя в одном месте
- **`infra/`** вместо `backend/guides/cicd.md` + `nginx.md`

## Что НЕ переносим из референса

- `mobile/` — нет мобильного клиента
- `analytics/` — для MVP логи в SQLite, без Posthog/Firebase
- `web/admin/` — нет веб-интерфейса
- `screens/` — нет UI скринов
- Бизнес-документы из `business/`-папки — у нас другой бизнес
