# INDEX — стартовый указатель для Claude

Что читать в начале сессии в зависимости от ситуации. Идея: не читать всё подряд, а сразу идти в нужное место.

## В начале каждой сессии (минимум)

1. **Auto-memory `MEMORY.md`** — короткие указатели на основные концепции и контекст
2. **`_claude/PROJECT-STATE.md`** — что готово, что в работе, ключевые решения
3. **`plans/*.md`** — есть незавершённые планы? Если да — предложить продолжить

Этих 3 файлов хватает чтобы понять "где мы и куда идём".

## По типу задачи

### "Начни новый день работы" (Шаг 1, 2, 3, ...)

Прочитать в порядке:
1. `_claude/PROJECT-STATE.md` (где сейчас)
2. `plans/` (есть план на этот день?)
3. `product_roadmap.md` (что должно быть в этом дне)
4. Конкретные файлы по теме дня (см. ниже)

### "Работаю с pipeline (Stage 0-5)"

1. `CLAUDE.md` — раздел "Архитектура pipeline"
2. `domain/pipeline.md` — контракт `process_user_request`, ранние выходы
3. `ai/<нужный_stage>.md` (`quality_check.md`, `scene_analysis.md`, ...)
4. `ai/prompts.md` — если меняю промпт
5. `ai/fail_patterns.md` — типичные провалы (если ищу почему не работает)

### "Работаю с ботом (диалог, FSM, команды)"

1. `domain/states.md` — FSM-состояния
2. `bot/flow.md` — полный путь пользователя
3. `bot/handlers.md` — паттерны обработчиков
4. `bot/onboarding.md` — туториал
5. `bot/commands.md` — `/start`, `/help`, ...

### "Работаю с базой данных"

1. `domain/data_model.md` — все таблицы и поля

### "Деплой на сервер / Docker"

1. `infra/server.md` — что уже на сервере, свободные порты, диск
2. `infra/docker.md` — Dockerfile, docker-compose
3. `_claude/DEPLOY.md` — конкретные команды

### "Подключение к OpenAI / Replicate / Telegram"

1. `ai/openai_vision.md` — OpenAI SDK, прокси через gptproxy
2. `ai/replicate.md` — все модели Replicate
3. `bot/handlers.md` — как взаимодействовать с aiogram

### "Что-то поломалось — расследую"

1. `_claude/PROJECT-STATE.md` — может это известная проблема
2. `ai/fail_patterns.md` — типичные провалы
3. `_claude/DECISIONS.md` — может это сознательное решение
4. Логи (`docker logs aiflatdesigner-bot`) и БД (`prototype.db`)

### "Архитектурное решение — почему так?"

1. `_claude/DECISIONS.md` — все большие решения с обоснованием

### "Секреты / токены / пароли"

1. `_claude/SECRETS.md` (gitignored, локально только)
2. `infra/secrets_template.md` — какие токены вообще нужны

### "Пользователь спрашивает про продукт / бюджет / план"

1. `product_brief.md` — целевая аудитория, use case
2. `product_roadmap.md` — план по дням, статус
3. `business/budget.md` — бюджет и unit-экономика

## Правила работы с памятью

1. **Перед фичей или багфиксом** — заглянуть в `domain/` и тематический файл (`ai/`, `bot/`).
2. **После решения** — записать в правильный файл и закоммитить.
3. **При фиче > 3 шагов** — создать `plans/<name>.md` (формат из `guides/plan_template.md`).
4. **При найденном грабле** — записать в `ai/fail_patterns.md` или `_claude/DECISIONS.md`.
5. **При смене подхода** — обновить `_claude/DECISIONS.md` с датой и причиной.
6. **При изменении статуса проекта** — обновить `_claude/PROJECT-STATE.md`.

## Анти-паттерны

- ❌ Читать `CLAUDE.md` целиком в начале каждой сессии — оверкилл, в нём 600 строк
- ❌ Читать все файлы в `ai/` если работаешь только с одним stage'ем
- ❌ Игнорировать `plans/` — там может лежать незавершённая работа
- ❌ Не обновлять `PROJECT-STATE.md` — через 3 сессии будет полная путаница

## Когда обновлять этот файл

Если в проекте появилась новая папка или важная концепция, под которую нет раздела "по типу задачи" — добавить.

Если какой-то файл перестал существовать (удалён, переименован) — почистить упоминания.

Если "минимум на сессию" расширился больше 4 файлов — переосмыслить, наверное что-то лишнее.
