# Bot Flow (полный путь пользователя)

⚠️ Текущее состояние: реализованы Шаги 1+2+2.5 (диалог, QC, pre-flight). Реальная генерация (Шаги 3-4) — заглушка `Принял всё. Запускаю подбор...`.

```
/start
  ↓
[первый раз] → ОНБОРДИНГ (Шаг 6, пока пропускается)
[не первый] → "Привет! Загрузи фото комнаты."
  ↓
[грузит фото СЦЕНЫ]
  ↓
⏳ "Проверяю фото (3-5 секунд)..."
  ↓
Stage 0: quality check scene
  ├── proceed → "✓ Сцена принята"
  ├── warn   → "⚠️ ... [Всё равно делать] [Загрузить другое]"
  └── reject → "❌ Это не похоже на фото интерьера"
  ↓
"Опиши комнату и высоту потолка одним сообщением.
 Пример: Часть гостиной 18м², потолки 270см"
  ↓
[парсинг потолка regex + сохранение описания]
  ↓
"✓ Понял: потолок 270см.
 Что заменить в комнате? Например: диван, кресло, обеденный стол..."
  ↓
[маппинг RU→EN через object_mapping]
  ↓
"✓ Заменяем: обеденный стол.
 Загрузи фото товара (как в каталоге — на белом фоне)."
  ↓
⏳ "Проверяю фото товара..."
  ↓
Stage 0: quality check product → proceed/warn/reject
  ↓
"Размеры товара в см? Формат длина x ширина x высота, например 140x90x76. Или 'не знаю'."
  ↓
[если 'не знаю' — пропускаем pre-flight, сразу в финал]
[если размеры → pre-flight check]
  ↓
⏳ "Проверяю влезет ли товар (5-10 секунд)..."
  ↓
Stage 1 (упрощённый): estimate_slot_dimensions через OpenAI vision
Stage 2: compare_product_to_slot (алгоритм)
  ↓
КЕЙС А: verdict=fits_ok
  → "✅ По моей оценке всё поместится. Запускаю подбор..."
  → финал (заглушка генерации Шаг 3-4)

КЕЙС Б: verdict=marginal (превышение 10-25%)
  → "⚠️ Товар на ~X% больше места. Что делаем?"
  → [✅ Всё равно попробовать] [🔄 Проверить размеры]

КЕЙС В: verdict=doesnt_fit (превышение >25%)
  → "❌ Товар на ~X% больше места. Возьми меньший размер."
  → [⚠️ Всё равно попробовать]

КЕЙС Г: is_target_appropriate_for_room=false
  → дополнительное предупреждение перед сравнением размеров
  ↓
[Шаг 3-4: реальная генерация — ещё не реализована]
```

## Лимиты

- **5 регенераций / пользователь / сутки.** При превышении — отказ с "Возвращайтесь завтра". Проверка через SQL по `generations.created_at`.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Запускает flow. Если пользователь новый — туториал; иначе сразу к делу. `state.clear()` |
| `/help` | Показывает туториал заново (любой пользователь) |
| `/cancel` | Сбрасывает текущий state. "Команда /start чтобы начать заново" |
| `/myhistory` | Последние 5 успешных генераций пользователя (для сравнения регенов) |

## Inline-кнопки (callback_data)

| Callback | Когда показывается | Что делает |
|---|---|---|
| `onb:next:N` (N=2,3,4) | Онбординг шаги | Переход на следующий шаг туториала |
| `onb:done` | Онбординг шаг 4 | `mark_user_onboarded`, переход в waiting_scene |
| `qc_scene:proceed` | QC scene = warn | Игнорируем warning, идём в waiting_room_dims |
| `qc_scene:retry` | QC scene = warn | Просим другое фото |
| `qc_product:proceed` | QC product = warn | Игнорируем warning, идём в waiting_product_dims |
| `qc_product:retry` | QC product = warn | Просим другое фото |
| `size_skip:yes` | size_mismatch | Повторный pipeline с `skip_size_check=True` |
| `size_skip:no` | size_mismatch | `state.clear()` + "Отменил" |
| `rate:{gen_id}:{rating}` | После успешной генерации | Сохранить rating в `generations.user_rating` |

## Edge cases в FSM

| Случай | Поведение |
|---|---|
| Пользователь шлёт текст вместо фото в waiting_scene | "Загрузите фото, не текст" — state не меняем |
| Пользователь шлёт несколько фото подряд | Игнорим все кроме последнего (FSM-handler возьмёт последнее `message.photo[-1]`) |
| Пользователь шлёт картинку как файл (document) | На MVP — отказ "Пришлите как фото, не как файл" |
| Пользователь шлёт `/start` посреди flow | `state.clear()`, начинаем заново (онбординг скипается если уже был) |
| Бот рестартовал — FSM потерян | Пользователь видит "Не понимаю команду", делает /start |
